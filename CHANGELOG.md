# История изменений

## [Unreleased]

- FIN-401/FIN-402: фактические расходы остаются отдельной плиткой, прогноз свежего текущего периода добавляется пятой. Пустой выбранный период не выдаётся за нулевые расходы. Блокировка прогноза поясняет всю загруженную историю: полные, неполные и отсутствующие месяцы из согласованного чтения месячных снимков; legacy/неполная доставка сохраняет общий текст без выдуманной базы. Расчёт и пороги, REST/protobuf и схема БД не меняются (контракт FIN-408).

- FIN-372: CI и линтеры используют общий источник `fin-assist/go-ci` по неизменяемому SHA; локальные команды и тесты скриптов используют проверенный кэш. Обновление и откат синхронизируют pins и копию bootstrap в одном PR. Runtime и публичный API не меняются.

- FIN-369: source provenance сохраняется в nullable JSONB состояния/заголовков с привязкой к calc_version строки, чтобы rollback/rollforward старого образа не оставлял ложный proof; более новый header/removal marker снимает state proof; GetAnalytics и непустой ListPeriods возвращают пересечение известных одинаковых ревизий всех использованных заголовков и состояния экрана. Повреждённые сохранённые null/нецелые значения не превращаются в известный ноль. Старые данные не получают выдуманной baseline, новые открытые коды и int64 сохраняются без потери. Clearing state убирает proof до final ACK полного календаря, включая daily/пустые ответы. Неверная metadata отклоняет весь ingest с прежним bare INVALID_ARGUMENT; версии/атомарность/purge прежние. Контракт — FIN-367, producer внедряется отдельным PR FIN-369 после FIN-357.

- FIN-5: реализован `GetAnalytics` из готовых снимков: единое чтение периода/состояния/навигации, все MVP-блоки и серверные тексты, supports/exp, текущий период и stale, частичная деградация и метрики недоступности блоков. Сохранённые версии определений продолжают показываться до атомарной замены; операции повторно не агрегируются, производные показа заданы действующими calc.md/api.md. После ревью добавлены проверки конкурентного default-чтения, populated tenant isolation и generic plan; исправлены подпись периода при смене пояса, независимость баланса от повреждённого monthly_chart, half-up без отрицательного нуля, heading/coverage и композиция small_frequent по calc.md §10. Месяцы точек и выбранный период берутся из ключей; при пересчёте без исходного IANA-пояса неподтверждённые дневные подписи заменяются периодом и явным partial/recalculating, финансовые границы не переписываются. Добавлены DST-регрессии near-midnight/end-of-day на трёх уровнях. В пустых текстах none примечания о неполных данных/пересчёте следуют после «нет», сохраняя смысл отрицания. Корректный action метрики сохраняется при отсутствующем фильтре крупнейшей small_frequent-группы.

### Добавлено

- `MetricsIngestService.UpsertUserMetrics`: проверка всего пакета по правилам «Инвариантов в коде сервиса» (`internal/domain`, голый `INVALID_ARGUMENT`, в том числе для `METRIC_STATUS_UNAVAILABLE` от производителя и периода и в снимках, и в удалениях), одна транзакция READ COMMITTED: tombstone guard, состояние, заголовки и метки, пропуски и метрики применённых ключей; удаление периода сравнивается с бо́льшей из версий двух режимов, версия метки только растёт; `lock.text` производителя игнорируется; `user_id` на границе приводится к каноническому нижнему регистру UUID, чтобы вызовы одного пользователя в разном регистре сериализовались на одном tombstone guard и совпадали с `sub`; период с одним режимом — предупреждение и `finassist_incomplete_period_snapshots_total{period_type}`. `AnalyticsService.ListPeriods` (смешанная модель: `bank-bff` с токеном пользователя, `assistant` с `user_id`) и `UserDeletionService.PurgeUserData` (`go-tombstone`); строки `AccessPolicy()` по grpc-api.md 3.3. На момент FIN-283 `GetAnalytics` оставался для FIN-5; реализован выше.
- `AUTH_MODE=verify` через `go-identity v0.2.0` `NewAssembly`: `ENV=prod` — ServiceAccount Kubernetes, `ENV=stage` — файлы ключей стенда, JWT пользователя — по ключам `user.GetSigningKeys`; новые переменные `AUTH_USER_*`, `AUTH_KUBERNETES_*`, `AUTH_STAGE_*`, обязательный `PEER_USER_ADDR`; `verify` при `ENV=dev` и неполные настройки — ошибка старта. `go-tombstone v0.1.0` вместо `NoTombstones`: источник миграций `tombstone` перед сервисным, `TOKEN_REVOKED` удалённому пользователю на любой вызов (FIN-282).

- FIN-148: CI сохраняет stage-бинарь из проверенного образа с SHA, manifest и контрольной суммой.

### Исправлено

- Шапка `deploy/systemd/analytics.service` предупреждает, что `EnvironmentFile=` перекрывает `Environment=`: env-файл стенда не должен повторять переменные, которые задаёт unit (`ENV`, `SERVICE_NAME`, `DB_PRIMARY_DSN_FILE`, пути `AUTH_STAGE_*`). Unit-тест сливает переменные в порядке systemd (env-файл поверх unit) и отклоняет env-файл, пересекающийся с переменными unit. Поведение сервиса не менялось (FIN-347, дополнение к analytics#28).
- Пример unit-файла стенда `deploy/systemd/analytics.service` запускается при `ENV=stage`: ключ подписи стенда передаётся через `LoadCredential=stage-signing`, `AUTH_STAGE_SIGNING_KEY_FILE` и `AUTH_STAGE_PUBLIC_KEYS_FILE` заданы активными `Environment=`, `SERVICE_NAME=analytics` (kid/sub ключа подписи) задаёт сам unit, шапка называет режимы файлов ключей (ключ 0600 root, общий JWKS 0644); в env-файле остаются `AUTH_STAGE_ISSUER`, `AUTH_USER_ISSUER`, `AUTH_USER_AUDIENCE`, `PEER_USER_ADDR`. Устаревший комментарий про `SERVICE_TOKEN_FILE` удалён; unit-тест загружает конфигурацию из unit-файла. Версии библиотек в `AGENTS.md`, README и `docs/` приведены к `go.mod` (go-postgres v0.3.0, go-migrate v0.1.1, go-grpc v0.2.0) (FIN-347).

### Изменено

- `go-grpc` v0.1.0 → v0.2.0: вызов смешанного метода от `bank-bff` без проверенного токена пользователя получает `INVALID_TOKEN`, а не системный вариант с `user_id` из запроса (FIN-299, нужен для `ListPeriods`). Предложенные в FIN-113 запросы записи и отображение снимка перенесены из тестов `migrations/` в репозиторий `internal/adapter/postgres/metrics.go`, тесты схемы — в тот же пакет; `ListPeriods` читает пояс и периоды одним оператором (FIN-283).
- `make test-names` проверяет и fuzz-цели (`FuzzUnit…`/`FuzzIntegration…`/`FuzzAPI…`, seed-корпус — в своём наборе) и отклоняет `Example…`; сборщики выбирают `^(Test|Fuzz)<Suite>` (FIN-290, перенос go-service-template#26).

- Документация приведена к шаблону и решениям: правило FIN-195 о нарушениях ограничений и полное правило схемы FIN-194 в `AGENTS.md`, актуальный статус `go-tombstone` в `docs/schema.md`, описание `GRPC_MAX_RECV_MSG_SIZE` по контракту analytics, ссылки README на задачи неподключённых RPC и identity/tombstone. Поведение сервиса не менялось (FIN-280).

- `docs/schema.md`: решённые открытые вопросы о повторе одной `calc_version`, удалении периодов после смены пояса, порядке выкатки нового поля метрики и `UNAVAILABLE`/`lock.text` от производителя заменены ссылками на правила контракта (`docs/grpc-api.md` 7.3, contracts#60); метка удалённого периода связана с правилом версий удаления из контракта (удаление сравнивается с бо́льшей из версий двух режимов и с существующей меткой, версия метки только растёт); названы тест `TestIntegrationRemovedPeriodStaysRemovedForOlderSnapshots`, чьё ожидание переворачивается в FIN-283, и правило, которое там сохраняется. Только документация: код, схема и API analytics не менялись (FIN-284, FIN-283).

- Общая инфраструктура подключена выпущенными `go-grpc`, `go-migrate`, `go-worker` v0.1.0 и `go-postgres` v0.2.0 вместо локальных копий; сохранены CLI, health/metrics, shutdown, реальные миграции и schema tests analytics.
